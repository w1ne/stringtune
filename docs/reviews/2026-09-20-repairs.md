# Tuner reliability repairs

The focused repair pass preserves the dark/pink appearance and Hugo/static-JavaScript architecture.

## Behavior and code changes

- Tuner owns a single microphone startup, explicit state, stream cleanup, and session tokens. Errors propagate to inline retry controls. Stop also cancels late permission grants and obsolete worklet callbacks.
- Reference tones initialize audio without microphone permission and play at reduced gain. Guitar, bass, and ukulele presets expose real string targets while retaining chromatic detection.
- Application clears idle/silent readings and spectrum, validates both saved and entered A4 (400–500 Hz), and uses a native keyboard-accessible calibration dialog. Notes rebuild without retaining detached elements. Meter renders exactly centered readings correctly.
- Mobile meter geometry, note strip, and footer gutters fit 320–1280px screens. The current visual identity and localized content remain. New guidance uses the existing Hugo English fallback.
- Offline manifest matches the versioned runtime assets and includes the worklet. Cache cleanup is scoped to this app; failed HTTP responses cannot poison working offline files.
- The dependency lockfile now matches Jest 29. CI runs lifecycle/cache tests, DOM tests, real WASM/worklet simulations, Rust tests, Hugo build, and browser flows.

## Bass accuracy

The dependency's finite-window autocorrelation candidate was biased toward shorter periods. The repair retains its candidate and clarity gates and refines only the nearby period using the energy of the overlapping sample pairs. This is phase-dependent normalization rather than a fixed frequency/cents correction.

`dsp.json` records the original measured bias; `dsp-after.json` records the updated bundled WASM. Across 26 synthetic sine/sample-rate combinations, the maximum absolute error was below 0.003 cents. This is synthetic accuracy only and does not establish real instrument, room-noise, or physical microphone performance.

### CSP audit interpretation

GitHub Pages does not support custom response headers, so the policy is delivered early in HTML. Lighthouse reports three medium advisories: prefer a response header, and add fallbacks for browsers without hash/strict-dynamic support. We retain the stronger policy instead of adding legacy script exceptions.

Lighthouse's `csp-xss` audit is informative (no numeric score), so its inherited `minScore` assertion cannot assess this policy. Its replacement checks the findings count and runs `scripts/verify-csp-report.cjs` as a required CI step. That check accepts only the three exact documented medium advisories and fails on missing reports, missing policies, bypasses, syntax errors or unknown findings. Unit tests verify those rejection paths. Browser tests independently prove that injected HTML scripts are blocked, while actual tuner processing and offline startup work.

References: [Lighthouse CSP audit implementation](https://github.com/GoogleChrome/lighthouse/blob/main/core/audits/csp-xss.js), [strict CSP guidance](https://web.dev/articles/strict-csp).
